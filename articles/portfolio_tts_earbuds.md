# Translation Earbuds Prototype — 公開APIで実現するリアルタイム翻訳音声

## 概要

**「Intent-First Translation」プロジェクトの拡張**として、リアルタイム翻訳基盤に音声読み上げ（TTS）を追加し、スマートフォンとBluetoothイヤホンの組み合わせで翻訳音声を耳で聞ける体験をどこまで実現できるかを検証した技術プロトタイプです。

Intent-First Translationでは、話し始めから約500ミリ秒で「何について話しているか」を画面に表示するリアルタイム翻訳システムを構築しました。本プロジェクトでは、その翻訳基盤（Deepgram音声認識 + LLMストリーミング翻訳）をそのまま活用し、翻訳結果を音声で読み上げるレイヤーを追加しています。

AppleのAirPods Pro ライブ翻訳（39,800円）やTimekettle M3（16,980円〜）は、専用ハードウェアと独自エコシステムにより完成度の高い翻訳イヤホン体験を提供しています。本プロジェクトでは、公開されているAPIとオープンな技術を組み合わせ、個人の開発でこの領域にどこまで近づけるかを検証しました。

## 実現できたこと

```
英語の発話 → スマホで音声認識 → LLMで翻訳（約2秒）
→ 日本語音声をBluetoothイヤホンから再生
```

- 翻訳テキストの表示と音声出力の遅延差は**約1秒以内**
- プロの同時通訳者（2〜3秒遅れ）に近いレイテンシ
- 専用ハードウェア不要、ブラウザ上で動作

## 検証の過程で解決した課題

| 課題 | 解決策 |
|------|--------|
| モバイルブラウザでTTS音声が再生されない | ユーザー操作でのオーディオロック解除 |
| PC/iPhoneで読み上げ速度が全く異なる | プラットフォーム判定による速度自動調整 |
| 翻訳が表示されても読み上げられないことがある | 発火条件の再設計と重複防止メカニズム |

## 検証で明らかになった制約

- **Bluetoothイヤホンのマイクは装着者の声に最適化されている** — 周囲の人の声は集音できない。AirPods Proや翻訳専用イヤホンがビームフォーミング技術を搭載するのは、この物理的制約を克服するため
- **ブラウザではオーディオ入出力デバイスの分離制御ができない** — iOSのWebKit制約。ネイティブアプリ（AVAudioSession）であれば制御可能
- **Web Speech APIの挙動はOSごとに大きく異なる** — 「ブラウザ標準API」でもクロスプラットフォームの動作保証はない

## 今後の展望

ブラウザベースの検証で技術的な可能性と限界を把握できたため、次のステップとしてネイティブアプリ（React Native / Swift）でのプロトタイプ開発を検討しています。ネイティブアプリであれば「入力=スマホ内蔵マイク / 出力=Bluetoothイヤホン」の分離制御が可能であり、今回のバックエンド（音声認識 + LLM翻訳）をそのまま活用できます。

## 技術スタック

| レイヤー | 技術 |
|---------|------|
| 音声認識 | Deepgram Streaming API |
| 翻訳・意図推定 | GPT-4 / Gemini Flash / Groq (LLM) |
| 音声読み上げ | Web Speech API (SpeechSynthesis) |
| リアルタイム通信 | WebSocket |
| フロントエンド | React + TypeScript |
| バックエンド | Python / FastAPI |

## 基盤プロジェクト

**Intent-First Translation** — 500msで意図を伝えるリアルタイム音声翻訳
本プロジェクトの基盤。話し始めから約500ミリ秒で「何について話しているか」を表示し、会話のテンポを維持するリアルタイム翻訳システム。本プロジェクトは、そのバックエンド（音声認識 + LLM翻訳パイプライン）をそのまま活用し、音声出力の可能性を検証する拡張実験として位置づけています。
